# ADR 0014：使用浏览器 Yjs 副本缩小协作硬崩溃丢失窗口

- 状态：Accepted
- 日期：2026-08-25
- 扩展：[ADR 0012](0012-use-yjs-for-team-document-collaboration.md) 的客户端恢复边界

## 背景

ADR 0012 以 PostgreSQL 中的完整 Yjs 状态作为 Team 正文权威，并让协作进程按周期和卸载时持久化。该设计能覆盖正常退出与可恢复存储故障，但 `SIGKILL`、OOM 或主机故障可能同时绕过周期存储和优雅关闭；如果所有浏览器随后关闭，最近一次成功数据库快照之后的更新会永久丢失。

浏览器已经持有同一篇文档的 Y.Doc。为它增加本地持久副本可以让重新打开页面的已授权用户把尚未进入服务端快照的更新重新合并回权威状态，但不能替代服务端持久更新日志，也不能承诺在所有客户端均不可用时达到 RPO=0。

## 决策

- Team 协作编辑器在服务端认证成功并授予 `read-write` scope 后，使用 `y-indexeddb` 持久化 Hocuspocus Provider 已有的同一个 Y.Doc；viewer、认证失败和 Personal 文档不挂载本地副本。
- IndexedDB 名称按 `knowmesh:<userId>:<documentId>:v<contentSchemaVersion>` 隔离。用户退出登录或删除账户时，只清理该用户前缀下的协作文档数据库。
- 编辑器等待服务端首次同步与本地副本首次加载完成后才挂载。任一链路失败时显示可见的降级状态，不把 Team 正文切换到 JSON 写入。
- 网络或协作服务断开后编辑器保持只读；本地副本只用于恢复与重连合并，不开放长期离线编辑。
- 服务端 Session、Project 权限和 `read-write` scope 始终是写入权威。本地缓存中的旧更新只有通过当前服务端授权后才能推送；降级为 viewer 或被移除的用户不能用缓存绕过授权。
- PostgreSQL 中的完整 Yjs 状态和 JSON 投影继续遵循 ADR 0012。本地副本是客户端辅助恢复层，不是服务端权威、审计日志或版本历史。

## 原因

- `y-indexeddb` 直接复用 Yjs 更新语义，不需要维护第二套正文合并协议。
- 先完成服务端认证再加载本地副本，避免只读或已撤权用户把旧缓存注入当前会话。
- 用户、文档和 Schema 版本共同组成命名空间，降低跨账户、跨文档和不兼容结构复用的风险。
- 保持断线只读，避免把有限的崩溃恢复机制误变成没有冲突、配额和清理策略的离线产品能力。

## 后果

- 在至少一个曾接收更新的授权浏览器仍保留本地站点数据时，服务端硬崩溃后的未落库更新可在重新连接时恢复。
- 无浏览器副本、站点数据被清除、浏览器存储失败或所有副本都丢失时，系统仍只能恢复最近一次成功的服务端快照；该限制必须继续纳入 RPO。
- IndexedDB 不保证在所有浏览器隐私模式或存储压力下可用；失败必须降级而不能阻塞只读访问。
- 账户退出流程需要尽力清理本地数据库。浏览器拒绝枚举或删除时不得阻止服务端退出，但需要记录不含正文的脱敏错误。
- 若未来要求“所有客户端消失后仍保证最近更新不丢失”或正式支持长期离线编辑，必须新增 ADR 设计服务端持久更新日志、确认协议、配额和冲突体验。

## 备选方案

### 仅缩短完整快照周期

未采用，因为更高频的完整状态编码和数据库写入增加负载，仍无法消除不可捕获终止发生在两个快照之间的窗口。

### 首阶段增加服务端逐更新日志

暂未采用，因为它需要设计去重、确认、压缩、恢复和清理协议。当前先用 Yjs 原生浏览器副本覆盖最常见的客户端辅助恢复场景。

### 允许断线继续编辑

未采用，因为当前产品没有离线状态、冲突预期、存储配额和撤权清理体验；本决策只处理硬崩溃恢复。
